# feat/performance-metrics-dataset

## [2026-07-02] PLANS.md 13번 성능 지표 측정 데이터 구성

### Descriptions

- PRD 10장의 Field Mapping Precision, Field Mapping Recall,
  Lineage Traceability 측정을 위한 독립 평가 dataset 생성 기능을 추가했다.
- `scala-backend generate-performance-dataset`은 Elasticsearch/Splunk 원천
  JSONL, `answer_key.json`, `dataset_manifest.json`을 결정적으로 생성한다.
- `scala-backend evaluate-performance-dataset`은 정답지 기준 지표를 계산하고
  `metrics.json`을 남긴다.
- `scala-backend export-performance-results`는 실제 performance pipeline 실행 후
  Redis mapping cache와 PostgreSQL lineage metadata에서 `actual_results.json`을
  추출한다. 평가기는 이 파일이 없으면 실패한다.
- 기존 개발 compose와 분리된 `docker-compose.performance.yml`과
  `docker-performance-*` Makefile target을 추가했다.
- 초기 평가에서 mapping recall이 낮게 나와, 보안 로그에서 일반적으로 쓰는
  source/destination, process, HTTP, auth field의 deterministic mapping fallback을
  보강했다.
- 평가 데이터는 증빙용 독립 데이터이며, 실제 운영 데이터나 기존 수동 테스트
  volume과 섞이지 않는다.

### Verification

- 독립 performance compose에서 seed -> JSON-RPC pipeline.run ->
  export-performance-results -> evaluate-performance-dataset 순서로 실행했다.
- 실제 Redis/PostgreSQL runtime 산출물 기준으로 Field Mapping Precision 1.0,
  Field Mapping Recall 1.0, Lineage Traceability 1.0을 확인했다.
- `uv run ruff check`, `uv run basedpyright`, `uv run mypy`, `uv run pytest`,
  `go test ./...`, `make docker-performance-config`를 통과했다.
