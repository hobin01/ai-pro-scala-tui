# main

## [2026-06-27] TUI 개발

### Descriptions

- `PLANS.md`의 "5. TUI 개발" 범위만 구현했다. 이후 단계인 백엔드, DB, Docker, JSON-RPC 연동은 구현하지 않았다.
- Go 모듈을 초기화하고 `cmd/scala-tui` 실행 파일, `internal/app` 모델/렌더링/더미 데이터, `Makefile`, `.golangci.yml`, QA 스크립트를 추가했다.
- Bubble Tea v2, Bubbles v2 spinner, Lip Gloss v2를 사용했다. Bubbles v2 최신 버전은 Go 1.25를 요구하므로 Go 1.24.4 환경에 맞는 `v2.0.0`으로 고정했다.
- 구현 화면은 Main, Source Selection, Data Samples, Agent Workflow Graph, Human Feedback, Lineage Viewer, Agent Monitoring, Settings다.
- 더미 데이터로 Elasticsearch, Splunk, OpenSearch source, sample fields, pipeline events, lineage record, monitoring snapshots, settings를 제공한다.
- Human Feedback 화면은 event 단위로 pipeline stream을 누적하고, 실행 중 input disabled, feedback 시 input/options enabled, approve 후 completion summary를 렌더한다.
- 검증은 `go test ./...`, `go test -race ./...`, `go vet ./...`, `go build -o bin/scala-tui ./cmd/scala-tui`로 수행했다.
- `golangci-lint`는 로컬에 설치되어 있지 않아 실행하지 못했고, `go vet`를 가능한 lint backstop으로 사용했다.
- 이 환경에는 `tmux`가 없어 QA 스크립트가 `expect` fallback을 사용한다. headless pseudo-tty transcript에는 Bubble Tea 본문이 직접 잡히지 않아, `TestBubbleTeaRendererOutputsInitialView`와 `TestScriptedFullFlowTranscript`를 통해 renderer 출력과 전체 화면 전환 transcript를 증거로 남겼다.
- 주요 evidence는 `.omo/ulw-loop/evidence/tui-regression.txt`, `.omo/ulw-loop/evidence/tui-scripted-flow.txt`, `.omo/ulw-loop/evidence/tui-happy-path.txt`에 있다.
- 리뷰에서 발견된 누락 상태를 보강했다. Main의 View Results 확장/직접 라우팅, Source 없음 상태, Data Samples 로딩/실패/Retry/Back/Open Settings, Lineage 조회 중/empty enter 복귀, Agent Workflow/Monitoring의 Caching no-LLM row, Monitoring read-only input, Settings 웹 콘솔 URL과 restart confirmation/restarting/complete flow를 추가했다.
- `internal/app/model.go`에 몰려 있던 상태 머신은 `routing.go`, `pipeline.go`, `lineage.go`, `settings.go`, `helpers.go`로 분리했고, 렌더링도 `view.go`, `view_pages.go`, `view_helpers.go`로 나눴다. 보강 후 production Go 파일은 모두 250 pure LOC 미만이다.
- 최종 리뷰 blocker를 해소했다. `View Results` 서브메뉴는 키보드로 실제 선택 가능하고, no-source 상태의 `space` panic을 막았으며, Agent Monitoring은 read-only 입력을 무시한다. Pipeline 실행 중 slash/text 입력도 차단한다.
- Settings의 pending restart는 Elasticsearch/Splunk/OpenSearch 필드별 플래그와 동적 restart 문구로 바꿨고, `View()` 렌더링 중 model 상태를 변경하던 monitoring 갱신도 제거했다.
- 테스트는 기능별 `_test.go` 파일로 분리했고, sleep 기반 renderer 테스트를 제거했다. 최종 검증 evidence는 `.omo/ulw-loop/evidence/tui-final-verification.txt`와 `.omo/evidence/tui-development-final-rereview-code-review.md`에 남겼다.

### Known boundaries

- 실제 Elasticsearch, Splunk, OpenSearch, PostgreSQL, Redis, ChromaDB, OpenAI, Docker, JSON-RPC 호출은 없다.
- Settings의 restart는 더미 상태 전환이며 실제 container나 service를 재시작하지 않는다.
- `.env`는 읽거나 수정하지 않았다.
