## TUI DESIGN

TUI : Terminal User Interface

주요 목적 : 터미널을 통해 `사용자`의 입력을 받은 뒤 `scala-agent`의 동작 과정, 처리 결과를 사용자에게 스트리밍으로 출력함

### 주요 key binding

| key input | 역할 |
| --- | --- |
| ↑ ↓ | 키보드 상하 입력으로 선택창 이동 |
| ← → | 키보드 좌우 입력으로 콘텐츠 페이지네이션 이동 |
| `space` | `space` 키 입력으로 단일, 복수 선택 기능 (선택 후 해제 포함) selector 역할일 때만 선택 기능을 하며, 그 외에는 공백 입력으로 사용됨 |
| `enter` | `enter` 키 입력으로 `사용자`의 현재 입력 내용 `scala`에게 전송 |
| `ctrl` + `enter` OR `shift` + `enter` | 줄바꿈 입력. `scala`에게 전송하면 안 됨 | 
| `ctrl` + c | 프로세스 강제 종료 | 
| `/` + <command> | command 입력기. 특정 페이지 이동, 명령어 help 기능 |

이외 필요한 key binding은 `tui-pages`에서 페이지 별로 정의한다.

### 전체 레이아웃 구조

화면은 모든 페이지에서 다음 4개 영역으로 고정한다.

```
┌─ SCALA · <부제/컨텍스트> ───────────────────────── <status> ─┐
│                                                              │
│   <Content>  — 페이지별 영역 (세로 스크롤, ←→ 페이지네이션)   │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│ > <input>                                                    │
└ ↑↓ move · enter select · /help · ctrl+c quit ───────────────┘
```

| 영역 | 위치 | 역할 |
|---|---|---|
| Header | 최상단 보더 | 좌측 `SCALA` 브랜드, 우측 상태 배지(`idle` / `running: <agent>…` / `sources: N`) |
| Content | 중앙 | 페이지별 본문(가이드/메뉴/스트리밍 출력/샘플 등). 세로 스크롤하며, 항목이 많으면 `←→`로 페이지네이션하고 `[n/m]` 인디케이터를 표시 |
| Input box | 하단 | 프롬프트 및 `/` 커맨드 입력. 항상 표시하되 `scala-agent` 동작 중에는 비활성화하고 `⌧ agent running…`을 표기. `human feedback` 요청 시에만 일시 활성 |
| Footer | 최하단 보더 | 현재 화면에서 유효한 키 힌트만 컨텍스트별로 노출 |

- 전체 인터랙션 방식은 **하이브리드**다. 선택 메뉴(↑↓·enter·space)가 1차 내비게이션이고, 입력창은 프롬프트와 `/` 커맨드 입력을 담당한다.
- `scala-agent`의 출력은 Content 영역에 스트리밍으로 출력하며, 진행 중에는 스피너/로딩 표기를 함께 노출한다.

### 공통 컴포넌트

페이지 전반에서 재사용하는 컴포넌트는 다음과 같다. (페이지별 상세는 `tui-pages`에서 정의)

| 컴포넌트 | 표기 | 설명 |
|---|---|---|
| 선택 메뉴 | `▸ item` + 하이라이트 | 현재 항목에 `▸` 마커와 강조색(reverse 옵션). ↑↓ 이동, enter 확정, space 다중 선택 |
| 상태 배지 | `idle` / `running: <agent>…` | Header 우측. 색으로 상태 구분(아래 색상 팔레트) |
| 키 힌트 푸터 | `↑↓ move · enter select …` | 현재 화면에서 유효한 키만 노출 |
| 입력창 | `> _` | 프롬프트·커맨드 입력. 비활성 시 `⌧ agent running…` |
| 로딩 표시 | 스피너 `⠋⠙⠹⠸…` / 모래시계 | 동작·재시동 등 진행 중 표시 |
| 에러 라인 | `✗ <message>` | 무효 입력·실패를 입력창 위에 한 줄로 표시. 에러색 |
| 페이지네이션 | `[n/m]` | Content가 여러 페이지일 때 표시. ←→ 이동 |
| 확정/성공 라인 | `✓ <message>` | 완료·성공 표시. 성공색 |

### TUI 개발 시 주의 사항

- 전체적인 Terminal UI 구성은 영어를 기본으로 구성한다. 
- 단, 한국어 입력과 한국어 출력을 지원해야 한다.
- 폰트와 글자 색이 있을 시, 검은 터미널 배경과 혼돈되지 않도록 어두운 계열은 사용하지 않는다.
- 글자와 박스의 구분이 필요한 경우, 비슷한 색을 사용하지 않는다. (ex. 파란색 글자, 하늘색 박스 -> 금지 대상)
- TUI 문구와 선택창, 입출력은 사람인 사용자가 쉽게 알아볼 수 있도록 간결한 문구, 명확한 구분과 공백으로 구성한다. 

### 색상 팔레트

위 "어두운 계열 금지" 제약을 구체화한 팔레트는 다음과 같다. 모두 검은 배경에서 충분히 밝은 색을 사용한다.

| 용도 | 색 (ANSI bright 권장) | 비고 |
|---|---|---|
| 브랜드·헤더·스텝 번호 | bright cyan | 강조 |
| 선택 항목 | bright green + `▸` | reverse 옵션 가능 |
| 본문 텍스트 | bright white | |
| 박스 보더 | white (밝은 회색) | 어두운 회색(bright black) 금지 |
| 상태 idle·주의 | bright yellow | |
| 상태 진행·성공(`✓`) | bright green | |
| 에러·무효 입력(`✗`) | bright red | |

- 보더와 텍스트에 동일하거나 유사한 색을 함께 쓰지 않는다. (예: cyan 보더 + 파랑 글자 금지)
- 색 외에 마커(`▸ ✓ ✗`)와 굵기/반전을 병행해, 색 구분이 어려운 환경에서도 의미가 전달되도록 한다.
