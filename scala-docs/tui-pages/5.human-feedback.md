# 5. Human Feedback

`scala-agent`가 **동작 중**인 상태에서 시작되는 화면이다. 진행 상황을 스트리밍으로 보여주고, agent가 판단하기 어려운 필드 매핑에 대해 사용자에게 피드백을 요청한다. **동작 중·동작 완료를 모두 담당**한다.

- 전체 레이아웃(Header / Content / Input / Footer)·색상·공통 컴포넌트는 `TUI-DESIGN.md`를 따른다.
- 기능 요구사항은 `FRD.md`의 `### 5.human-feedback.md`를 기준으로 한다.
- 진입: `4.agent-workflow-graph`에서 `Start pipeline` 선택 시.

**입력 활성 규칙**: 동작 중에는 입력 비활성(`⌧ agent running`). **human feedback 요청 시에만** 입력 활성. (esc 인터럽트는 제거됐으므로 동작 중 중단은 없다.)

**흐름**: A(동작 중) ↔ B(feedback 요청) 를 모든 매핑이 끝날 때까지 **반복**하고, 완료되면 D(결과)로 간 뒤 `enter`로 `1.main`으로 이동한다.

---

## State A — 동작 중 (feedback 없음)

agent별 진행을 thinking 로그로 스트리밍한다. 입력은 비활성이다.

```
┌─ SCALA · Pipeline running ─────────────────── running: Normalization ─┐
│  run #a1b2c3 · sources: 4                                             │
│                                                                      │
│  ✓ Orchestrator      started pipeline                                │
│  ✓ Schema Profiler   profiled 13 fields  (cache 8 hit · 5 miss)      │
│  ✓ Schema Profiler   matched OCSF candidates (ChromaDB)              │
│  ⠹ Normalization     generating mapping rules…                       │
│                                                                      │
│  Mapping progress  ████████░░░░░░░░  8 / 13 fields                    │
│                                                                      │
├──────────────────────────────────────────────────────────────────────┤
│ ⌧ agent running — input disabled                                     │
└ ctrl+c quit ────────────────────────────────────────────────────────┘
```

- `✓` 완료 단계 · `⠹` 현재 진행(스피너). Header 우측은 현재 동작 중인 agent.
- thinking 로그 구현 난이도가 높으면 `⠹ agent running…` 한 줄로 축소해도 된다. (FRD 허용)

## State B — Human feedback 요청 (입력 활성)

한 번에 **한 필드씩** 요청한다. 원본 필드/타입, 샘플, 추천 OCSF 필드/타입(또는 raw 유지 추천)과 이유를 보여주고 3선택을 받는다.

```
┌─ SCALA · Human feedback needed ──────────────────────── needs input ─┐
│  run #a1b2c3 · Splunk · main                                         │
│                                                                      │
│  ⚑ The agent is unsure about this field.                             │
│    Source field   clientip          (string)                         │
│    Sample values  "10.0.0.5" · "192.168.1.20"                        │
│    Recommended    src_endpoint.ip   (OCSF, ip)                       │
│    Why            name+value look like a source IP; cast string→ip    │
│                                                                      │
│  How should this map?                                                │
│    ▸ Approve recommendation   → src_endpoint.ip                      │
│      Keep raw                 → clientip (custom_attr)               │
│      Comment & re-review      → give the agent a hint                │
│                                                                      │
├──────────────────────────────────────────────────────────────────────┤
│ > _                                                                  │
└ ↑↓ move · enter select · /help ─────────────────────────────────────┘
```

- `Approve recommendation` = 추천 승인 · `Keep raw` = raw 유지(`custom_attr`/`unmapped_field`) · `Comment & re-review` = 의견 작성 후 재검토.
- `Approve`/`Keep raw` 선택 시 즉시 적용 후 다음 단계로 진행한다.

## State C — "Comment & re-review" 선택 (의견 입력)

입력창에 힌트를 타이핑하고 `enter`로 전송하면, agent가 재검토 후 갱신된 추천을 다시 제시한다(State B 재진입).

```
│  How should this map?                                                │
│      Approve recommendation                                          │
│      Keep raw                                                        │
│    ▸ Comment & re-review     (type a hint below, enter sends)        │
├──────────────────────────────────────────────────────────────────────┤
│ > this is the proxy client ip, prefer x_forwarded_for_              │
└ enter send · ctrl+enter newline · ↑↓ pick another option ───────────┘
```

- 입력 중 `↑↓`로 다른 선택지로 이동하면 입력 중인 힌트는 버려지고 해당 선택지로 전환한다.

## State D — 완료 (Orchestrator 결과 + OpenSearch 링크)

모든 매핑이 끝나고 OpenSearch 적재까지 완료되면, Orchestrator가 결과 요약과 OpenSearch 링크를 보여준다.

```
┌─ SCALA · Pipeline complete ──────────────────────────────── done ─┐
│  run #a1b2c3 · sources: 4                                         │
│                                                                  │
│  ✓ Normalization complete   13 mapped · 2 kept raw (custom_attr) │
│  ✓ Loaded 2,000 docs to OpenSearch  (scala-normalized)           │
│  ✓ Lineage recorded for 2,000 docs  (PostgreSQL)                 │
│  ✓ 5 mappings cached  (Redis)                                    │
│                                                                  │
│  View results in OpenSearch:                                     │
│    https://opensearch.local/_dashboards/…  (scala-normalized)    │
│                                                                  │
├──────────────────────────────────────────────────────────────────┤
│ Press enter to return to main.                                   │
└ enter main · /help ──────────────────────────────────────────────┘
```

- 적재 건수(예: 2,000)는 선택된 소스의 합과 일치한다. (PRD §9 기준 ES 1000 + Splunk 1000 = 2,000)

## 화면 전환

| 동작 | 전환 |
|---|---|
| (`4`에서) `Start pipeline` | 이 화면 진입, State A에서 시작 |
| feedback 필요 발생 | State A → State B (입력 활성) |
| `Approve recommendation` / `Keep raw` | 적용 후 State A(다음 단계)로 |
| `Comment & re-review` → `enter` 전송 | agent 재검토 후 State B(갱신된 추천) |
| 모든 매핑·적재 완료 | State D(결과) 표시 |
| State D에서 `enter` | `1.main` 화면으로 이동 |

## 페이지 고유 동작

- feedback 요청/응답은 화면상 "the agent"로 일반 표기하지만, `사용자`와의 채널은 **Orchestrator가 중계**한다. 추천 매핑 내용은 Profiler/Normalization이 생성하고 Orchestrator는 전달만 한다. (`PRD.md` mermaid 8~11번과 일치)
- `Approve`·`Comment & re-review` 결과는 Validator가 **수용 전 한 번 더 자가 검증**한 뒤 반영한다. ([FRD.md](../FRD.md) Validator Agent 참고)
- 동작 중에는 모든 사용자 입력(프롬프트, `/` 커맨드)을 받지 않는다. 큐잉 시스템이 없으므로, feedback 요청 시에만 입력이 일시 활성화된다.
- 결과·진행 출력은 스트리밍으로 표시한다.
