# 4. Agent Workflow Graph

현재 구성된 `scala-agent`의 워크플로우 구성을 확인하는 화면이다. 화려한 그래프 시각화가 목적이 아니라, **어떤 agent가 어떤 역할을, 어떤 흐름으로** 수행하는지 설명하는 것이 목적이다. (거의 정적 화면)

- 전체 레이아웃(Header / Content / Input / Footer)·색상·공통 컴포넌트는 `TUI-DESIGN.md`를 따른다.
- 기능 요구사항은 `FRD.md`의 `### 4.agent-workflow-graph.md`를 기준으로 한다.
- 표현 항목: ① agent 간 구성도/흐름(`PRD.md`의 `7. 주요 워크플로우` mermaid 압축) ② 각 agent 역할 ③ 각 agent 모델.

**두 가지 진입 모드** (FRD):
- **뷰 모드** — main에서 `/agent-workflow`로 단순 조회. `enter` 시 **main 복귀**.
- **파이프라인 게이트 모드** — `3.data-samples` 이후 진입. `enter`(시작 선택) 시 **`5.human-feedback`로 이동**.

**모델 표기**: `gpt-…`는 자리표시자이며, 실제로는 **Settings(config)의 agent별 model 설정값**을 표시한다. `Load · Caching · Lineage`는 결정론적 실행자로 LLM을 사용하지 않으므로 `— (no LLM)`로 표기한다.

---

## State A — 뷰 모드 (main에서 단순 조회)

```
┌─ SCALA · Agent workflow graph ───────────────────────── idle ─┐
│                                                               │
│  How SCALA processes your data (LangGraph pipeline)           │
│                                                               │
│  User                                                         │
│   └─▶ Orchestrator                                            │
│         └─▶ Schema Profiler   ⟷ Redis cache · ChromaDB OCSF   │
│               └─▶ Normalization                               │
│                     └─▶ Validator   ⟷ User (feedback via OA)  │
│                           └─▶ finalize rules                  │
│                                 ├─▶ Load     ▶ OpenSearch     │
│                                 ├─▶ Caching  ▶ Redis          │
│                                 └─▶ Lineage  ▶ PostgreSQL     │
│                                       └─▶ Orchestrator ▶ User │
│                                                               │
│  Agent            Role                        Model           │
│  ───────────────  ──────────────────────────  ─────────────   │
│  Orchestrator     workflow 관리 · 사용자 소통   gpt-…          │
│  Schema Profiler  스키마 프로파일 · 캐시 조회    gpt-…-mini     │
│  Normalization    정규화 Rule 생성 · 적용       gpt-…          │
│  Validator        데이터 정합성 검증            gpt-…-mini     │
│  Load             정규화 데이터 적재            — (no LLM)     │
│  Caching          매핑 캐시 저장                — (no LLM)     │
│  Lineage          리니지 메타데이터 생성         — (no LLM)     │
│                                                               │
├─────────────────────────────────────────────────────────────────┤
│ enter to return to main.                                      │
└ ↑↓ scroll · enter back · /help ──────────────────────────────┘
```

- 흐름도는 `PRD.md` mermaid를 터미널용으로 압축한 것이다. (Human Feedback은 Orchestrator 중계, 최종 결과도 Orchestrator가 사용자에게 전달 — PRD와 일치)
- 그래프/표가 한 화면을 넘으면 `↑↓`로 스크롤한다.

## State B — 파이프라인 게이트 모드 (`3.data-samples` 이후)

그래프/레전드(State A의 Content)는 동일하고, **Header 상태와 하단 액션만** 시작 확인으로 바뀐다.

```
┌─ SCALA · Agent workflow graph ───────────────── ready · sources: 4 ─┐
│                                                                    │
│  (State A와 동일한 흐름도 + agent 레전드)                            │
│                                                                    │
├──────────────────────────────────────────────────────────────────────┤
│  Run the normalization pipeline on 4 selected sources?             │
│    ▸ Start pipeline        Back to samples                         │
└ ↑↓ scroll · enter select · /help ─────────────────────────────────┘
```

- `Start pipeline` → `5.human-feedback` (scala-agent 동작 시작) · `Back to samples` → `3.data-samples`.
- Header는 모드에 따라 `idle`(뷰) ↔ `ready · sources: N`(게이트).

## 화면 전환

| 진입 모드 | 동작 | 전환 |
|---|---|---|
| 뷰 모드 (main `/agent-workflow`) | `enter` | `1.main` 화면으로 복귀 |
| 게이트 모드 (`3.data-samples` 이후) | `Start pipeline` 선택 | `5.human-feedback` 화면 (동작 시작) |
| 게이트 모드 | `Back to samples` 선택 | `3.data-samples` 화면 |
| 공통 | `↑↓` | 흐름도·레전드 스크롤 |
| 공통 | `/help` | 도움말 표시 |

## 페이지 고유 동작

- 현재 프로젝트 범위에서 이 화면은 **거의 정적**이다. (실시간 그래프 변화 없음)
- 진입 모드는 어디서 왔는지로 결정된다: 단순 조회(main) vs 소스 선택 흐름(`3.data-samples`).
- agent 모델명은 `8.settings`(config)에 설정된 값을 표시하며, Settings에서 변경 시 이 화면에도 반영된다.
- `Load · Caching · Lineage`는 LLM을 사용하지 않으므로 모델 칸이 `— (no LLM)`이고, `7.agent-monitoring`에서도 토큰 0으로 일관된다.
