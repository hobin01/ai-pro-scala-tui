# 3. Data Samples

`2.source-selection`에서 선택된 index들의 **필드 · 타입 · 값 샘플**을 확인하는 화면이다. source solution의 SDK로 데이터를 일부 가져와 보여준다.

- 전체 레이아웃(Header / Content / Input / Footer)·색상·공통 컴포넌트는 `TUI-DESIGN.md`를 따른다.
- 기능 요구사항은 `FRD.md`의 `### 3.data-samples.md`를 기준으로 한다.
- 샘플은 **최대 5개**, 필드는 **실데이터의 모든 필드**를 보여준다.

**멀티 인덱스 처리**: page 2에서 2개 이상 선택되므로, **선택된 index 하나당 1페이지**로 보고 `←→`로 인덱스 간 이동한다(Header에 `[n/m]`). 현재 인덱스의 필드가 한 화면을 넘으면 `↑↓`로 스크롤한다.

**테이블 레이아웃**: 필드 지향(transposed) — `Field · Type · Sample values`. 필드당 샘플 값을 최대 5개까지 `·`로 나열한다. (행 상관관계 대신 이기종 필드/타입 비교 가독성을 우선)

---

## State A — 로딩 (소스별 fetch 진행)

선택된 각 소스에 대해 SDK 조회가 진행되는 동안 소스별 진행 상태를 표시한다.

```
┌─ SCALA · Data samples ─────────────────────────── fetching… ─┐
│                                                              │
│  ⠹ Fetching samples from selected sources…                   │
│    Elasticsearch · logs-2024     ✓                           │
│    Elasticsearch · firewall-idx  ⠹                           │
│    Splunk · main                 ·                           │
│    Splunk · security             ·                           │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

- `✓` 완료 · `⠹` 진행 중(스피너) · `·` 대기.

## State B — 인덱스 샘플 (Elasticsearch)

```
┌─ SCALA · Data samples ───────── [1/4] Elasticsearch · logs-2024 ─┐
│  5 samples · 7 fields                                           │
│                                                                 │
│  Field         Type     Sample values (≤5)                      │
│  ────────────  ───────  ──────────────────────────────────────  │
│  @timestamp    date     2026-06-25T01:02:03Z · 2026-06-25T01:…   │
│  src_ip        ip       10.0.0.5 · 192.168.1.20 · 172.16.0.9     │
│  dst_port      long     443 · 8080 · 22 · 53 · 3389              │
│  action        keyword  allow · deny                            │
│  user_name     text     alice · bob · (null)                    │
│  bytes_out     long     1240 · 88 · 4096                         │
│  tmp_note      text     "test" · "" · check-later               │
├──────────────────────────────────────────────────────────────────┤
│ Press enter to continue to the agent workflow graph.            │
└ ←→ index · ↑↓ scroll · enter continue · /help ──────────────────┘
```

- `Header [1/4]`는 선택된 인덱스 중 현재 페이지/전체 수.
- 결측치는 `(null)`, 빈 문자열은 `""`로 그대로 표기해 데이터 품질을 드러낸다.

## State C — 이기종 필드 (Splunk)

같은 의미의 필드가 다른 이름·타입으로 들어오는 모습을 그대로 보여준다. (SCALA가 정규화로 해결할 대상)

```
┌─ SCALA · Data samples ───────── [3/4] Splunk · main ─┐
│  5 samples · 6 fields                                │
│                                                      │
│  Field         Type     Sample values (≤5)           │
│  ────────────  ───────  ───────────────────────────  │
│  _time         string   2026-06-25 01:02:03          │
│  clientip      string   "10.0.0.5" · "192.168.1.20"  │
│  port          string   "443" · "8080"               │
│  status        string   allow · block                │
│  src_user      string   alice · — · bob              │
│  raw_msg       string   "...syslog text..."          │
├──────────────────────────────────────────────────────┤
│ Press enter to continue to the agent workflow graph. │
└ ←→ index · ↑↓ scroll · enter continue · /help ───────┘
```

- 위 ES `src_ip`(ip) ↔ Splunk `clientip`(string), ES `dst_port`(long) ↔ Splunk `port`(string `"443"`)처럼, 이름·타입 불일치를 사용자가 직접 확인할 수 있다.

## State D — fetch 실패

이 화면에서 실제 소스 연결이 처음 일어나므로, 연결 실패는 여기서 표면화된다.

```
┌─ SCALA · Data samples ──── [2/4] Elasticsearch · firewall-idx ─┐
│                                                               │
│  ✗ Could not fetch samples from this source.                  │
│    es-prod · firewall-idx                                     │
│    Connection refused (https://es-prod:9200).                 │
│                                                               │
│    ▸ Retry      Back to sources      Open Settings            │
│                                                               │
├─────────────────────────────────────────────────────────────────┤
│ > _                                                           │
└ ←→ index · enter retry · /settings · /help ──────────────────┘
```

- `Retry` 재조회 · `Back to sources` → `2.source-selection` · `Open Settings` → `8.settings`(연결 url 수정).

---

## 화면 전환

| 동작 | 전환 |
|---|---|
| `enter` | `4.agent-workflow-graph` 화면 (전환 안내 후 이동) |
| `←→` | 선택된 인덱스 페이지 간 이동 (`[n/m]`) |
| `↑↓` | 현재 인덱스의 필드 목록 스크롤 (필드가 한 화면을 넘을 때) |
| `Retry` (에러 시) | 해당 소스 재조회 |
| `Back to sources` (에러 시) | `2.source-selection` 화면 |
| `/settings` | `8.settings` 화면 |
| `/help` | 도움말 표시 |

## 페이지 고유 동작

- 샘플과 필드는 SDK로 조회한 **실데이터**다. (page 2의 정적 목록과 달리 실제 연결이 일어나는 첫 지점)
- 필드당 샘플 값은 최대 5개까지 나열한다. 값이 길면 말줄임(`…`)으로 자른다.
- 결측치·빈 값·오탈자 필드도 가공 없이 그대로 표기해 데이터 상태를 사용자가 판단할 수 있게 한다.
- 모든 인덱스를 확인할 필요 없이, 언제든 `enter`로 다음 단계(`4.agent-workflow-graph`)로 진행할 수 있다.
