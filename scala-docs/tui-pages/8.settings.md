# 8. Settings

설정값을 **확인·수정**하는 화면이다. 수정은 `scala_settings` table에 반영되어 다른 화면에도 적용된다.

- 전체 레이아웃(Header / Content / Input / Footer)·색상·공통 컴포넌트는 `TUI-DESIGN.md`를 따른다.
- 기능 요구사항은 `FRD.md`의 `### 8.settings.md`를 기준으로 한다.
- 설정 가능한 모든 값은 setting table에서 관리되는 값과 **항상 동일**하다(단일 출처).
- 필수 설정값: agent별 model · OpenAI API key · source url · 연결 가능 index · OpenSearch url · OpenSearch result index. + 웹 콘솔 URL(Kibana / Splunk Web / OpenSearch Dashboards).

**편집 방식**: `↑↓`로 필드 이동, `enter`로 편집(하단 입력창을 에디터로 재사용). `enter`가 main 이동과 겹치지 않도록, main 복귀는 목록의 **`Back to main`** 항목으로 한다.

**반영 방식 (두 갈래)**:
- **즉시 반영(hot-reload)** — index 추가/모델/시스템 프롬프트 등. 특히 **index 추가는 프로세스 종료 없이 `1.main`·`2.source-selection`에서 바로 선택 가능**(FRD 명시).
- **재시작 필요** — 일부 항목(예: URL)은 `* pending`으로 표시만 하고 재시작은 미룬다. 편집을 마친 뒤 **사용자 확인을 받아 한 번에 일괄 재시작**한다. (편집 1건마다 재시작하지 않는다.)

**API key 취급**: API key는 secret이므로 **TUI에서 수정하지 않는다.** 개요(State A)에 **마스킹·읽기 전용**으로만 표시하고(키 설정 여부 확인용), 변경은 `.env`에서 직접 한다.

---

## State A — 설정 개요 (pending 표시)

재시작이 필요한 변경이 있으면 Header에 개수, 해당 필드에 `* pending`, 목록에 `Apply pending changes`를 표시한다.

```
┌─ SCALA · Settings ───────────────────── 2 changes pending restart ─┐
│  Agents & model                                                   │
│    ▸ Orchestrator model    gpt-…                                  │
│      Schema Profiler model gpt-…-mini                             │
│      Normalization model   gpt-…                                  │
│      Validator model       gpt-…-mini                             │
│      OpenAI API key        sk-…••••3f9a   (read-only · .env)      │
│                                                                   │
│  Sources                                                          │
│      Elasticsearch URL     https://es-prod:9201        * pending  │
│        indices             logs-2024 · firewall-idx     (+ add)   │
│      Splunk URL            https://splunk-soc:8089               │
│        indices             main · security              (+ add)   │
│                                                                   │
│  Output (OpenSearch)                                              │
│      OpenSearch URL        https://opensearch.local:9201 * pending│
│      Result index          scala-normalized                       │
│                                                                   │
│  Web consoles (open in browser)                                   │
│      Kibana                https://kibana.local:5601             │
│      Splunk Web            https://splunk-soc:8000               │
│      OpenSearch Dashboards https://opensearch.local:5601         │
│                                                                   │
│    ▸ Apply pending changes (restart)                              │
│      Back to main                                                 │
├───────────────────────────────────────────────────────────────────┤
│ ⌧ select a field to edit                                          │
└ ↑↓ move · enter edit · space toggle/add · /help ─────────────────┘
```

- `* pending` = 새 값이 `scala_settings` table에는 저장됐으나, 적용에는 재시작이 필요한 항목.
- pending이 없으면 Header는 `idle`이고 `Apply pending changes` 항목은 표시되지 않는다.
- agent model은 LLM 4종만 편집한다. (Load·Caching·Lineage는 no-LLM이라 model 없음)
- **OpenAI API key 행은 읽기 전용**이다. secret이므로 `.env`에서 관리하며, `enter`로 편집되지 않는다. (TUI는 secret을 쓰지 않음)

## State B — 필드 편집 (하단 입력창을 에디터로)

```
│  Output (OpenSearch)                                              │
│      OpenSearch URL        https://opensearch.local:9201 * pending│
│    ▸ Result index          [editing…]                             │
├───────────────────────────────────────────────────────────────────┤
│ Edit · Result index                                               │
│ > scala-normalized_                                               │
└ enter save · ↑↓ cancel edit · /help ─────────────────────────────┘
```

- `enter` 저장 · `↑↓`로 다른 필드 이동 시 편집 취소.
- API key 행은 읽기 전용이라 편집 모드로 들어가지 않는다. (변경은 `.env`에서)
- 저장 시 hot-reload 항목은 즉시 반영, 재시작 필요 항목은 `* pending`으로 표시된다.

## State C-confirm — 재시작 허락

`Apply pending changes` 선택 시(또는 pending이 있는 채로 `Back to main` 시도 시) 확인을 받는다.

```
│  ⚑ 2 changes need a restart to take effect:                       │
│      Elasticsearch URL · OpenSearch URL                           │
│    Restart the affected containers now?                           │
│      ▸ Restart now      Keep editing      Leave without restart   │
```

- `Restart now` → State C(재시작) · `Keep editing` → State A · `Leave without restart` → `1.main`(다음 재시작 시 반영, 안내 문구 표시).

## State C — 재시작 중 (이동 불가)

영향받는 컨테이너만 재시작한다. 재시작 중에는 main 이동이 불가능하다.

```
┌─ SCALA · Settings ──────────────────────────── restarting… ─┐
│  ⠹ Applying changes — restarting affected containers…       │
│    ✓ settings saved                                           │
│    ✓ restart: elasticsearch-conn                            │
│    ⠹ restart: opensearch                                    │
│                                                             │
│    Navigation is disabled until restart completes.          │
├───────────────────────────────────────────────────────────────┤
│ ⌧ restarting — please wait                                  │
└ (navigation disabled) ─────────────────────────────────────┘
```

## State D — 적용 완료 알림

```
│  ✓ Restart complete · all affected containers are back up.  │
│  ✓ Settings applied.                                        │
```

완료 후 State A(개요)로 돌아가며, Header는 `idle`(pending 0)로 갱신된다.

## 화면 전환

| 동작 | 전환 |
|---|---|
| 진입 | `1.main`의 "Settings" 또는 `/settings` |
| `enter` (필드 위) | 해당 필드 편집(State B) |
| `space` (index 행) | index 선택/추가 토글 (hot-reload) |
| `Apply pending changes` | State C-confirm |
| `Back to main` (pending 없음) | `1.main` 화면 |
| `Back to main` (pending 있음) | State C-confirm |
| `Restart now` | State C(재시작) → State D → State A |
| 재시작 중 | main 이동 차단 |
| `/help` | 도움말 표시 |

## 페이지 고유 동작

- 모든 설정값은 setting table과 항상 동일하다. 사용자가 설정 저장 요청 시 table에 저장된다.
- hot-reload 항목은 저장 즉시 다른 화면에 반영된다. (특히 index 추가는 종료 없이 바로 선택 가능)
- 재시작이 필요한 변경은 누적해 두었다가, 사용자 확인 후 **한 번에** 영향받는 컨테이너만 재시작한다.
- API key는 개요에 마스킹·읽기 전용으로만 표시하며, TUI에서 수정할 수 없다. 변경은 `.env`에서 직접 한다.
- 웹 콘솔(Kibana/Splunk Web/OpenSearch Dashboards) URL은 사용자가 브라우저로 열어 원본·정규화 데이터를 확인하는 용도로 표시만 한다.
